# C4Bridge v0.2.0

The OpenAPI release: the LAN API is now a standard, documented REST API with logical names, API keys and a log for debugging. This release breaks compatibility with the alpha API — pair browsers again after updating.

## API

- Described by OpenAPI 3.1: [`api/openapi.yaml`](../../api/openapi.yaml). The bridge serves it at `/v1/openapi.json` and this release attaches it as `openapi.json`.
- Logical resources: `system`, `rooms`, `devices`, `lights`, `thermostats`, `logs`, `api-keys`. No Control4 command names, proxy IDs or variable numbers.
- Changes use `PATCH` with the desired state, e.g. `PATCH /v1/lights/{id}` `{"brightness": 40}` or `PATCH /v1/thermostats/{id}` `{"mode": "cool", "target_temperature": 22}`.
- Errors use RFC 9457 Problem Details with a stable `code`.
- Filters: `/v1/devices?room_id=&type=&supported=`, `/v1/lights?room_id=`, `/v1/thermostats?room_id=`.

## Authentication

- Every route except `GET /v1/health`, `GET /v1/openapi.json` and `POST /v1/auth/pair` needs `Authorization: Bearer <api key>`.
- Pairing with the Composer code now issues a named API key; more keys can be created, listed and revoked under `/v1/api-keys` (up to 20).
- New Composer actions: **New Pairing Code** and **Revoke All API Keys**. The pairing code also renews itself when it expires.

## Debugging

- `GET /v1/logs` returns the bridge's last 500 log entries — API requests, device commands, state changes, errors — filtered by level, category and sequence number.
- The log level is set with `PATCH /v1/logs/settings` or the new Composer **Log Level** property. Secrets are never logged.
- The API starts before project discovery, so health and logs stay reachable if discovery fails.

## Web app

- Dashboard moved to the new API.
- New API console: lists every endpoint from the live API description, sends requests, and follows the log.

## Driver and project

- HTTP server rewritten: requests are assembled from raw data, so request bodies work.
- Driver tests run the real driver against a fake Director in CI.
- `VERSION` (`MAJOR.MINOR.PATCH`) is the only version to edit; the build stamps it into the driver. The Control4 driver version is now `200`.
- Composer properties renamed: Version, Controller OS, Location, Inventory, API Keys, Log Level.

## Removed

`/v1/system/info`, `/v1/climate`, `/v1/diagnostics`, `/v1/devices/{id}/actions/*` and the header-based `/v1/pair`.

## Validation

Validated on a real Director 3.4.3 system: pairing, lights, thermostats, browser preflights, and 83 real responses checked against the API description with zero schema errors (see `docs/VALIDATION.md`).

## Known issues

- Updating the driver may still need a Director reboot before the new version loads (issue #8).
- KNX percentage dimming remains deferred (issue #11).
