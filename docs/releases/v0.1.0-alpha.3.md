# C4Bridge v0.1.0-alpha.3

First real device-control build.

## Compatibility

- Minimum Director OS: **3.3.0**
- Production PWA: **https://app.c4bridge.io**
- LAN API port: **41999**
- Tested transport baseline: Director 3.4.3 / CORE 1 from alpha.2

## Included

Everything from alpha.2, plus the first supported device adapter:

### Light V2

C4Bridge now initializes standard Control4 `light_v2` proxy devices using the documented proxy variables:

- Light State — variable ID `1000`
- Light Brightness Percent — variable ID `1001` when available
- Default On Preset Brightness — variable ID `1006` when available

Supported normalized actions:

- `on`
- `off`
- `set_brightness` for dimmable lights

Commands are translated internally to the Light V2 `SET_BRIGHTNESS_TARGET` proxy command. The browser never sends raw Control4 command names.

### Live state

C4Bridge registers variable listeners for supported lights. State changes reported by Control4 update the in-memory registry, including changes made from wall keypads, Composer, Navigator, or C4Bridge.

### API

New:

- `GET /v1/lights`
- `POST /v1/devices/{id}/actions/on`
- `POST /v1/devices/{id}/actions/off`
- `POST /v1/devices/{id}/actions/set_brightness?value=0..100`

All endpoints require the existing Bearer token. CORS remains limited to official C4Bridge origins.

### Web app

The live PWA now shows a dedicated Lights panel with:

- current On/Off state
- brightness percentage for dimmers
- On button
- Off button
- brightness slider for dimmers
- manual state refresh

## Composer properties

After updating:

- **Bridge Version:** `0.1.0-alpha.3`
- **Status:** `Ready (light adapter initialized)`
- **Supported Lights:** non-zero when Light V2 proxies are present
- **API Status:** `Online - light control alpha`
- **API Port:** `41999`

The API token is preserved across the driver update.

## Test carefully

For the first test, choose one light whose physical location you can see.

1. Open **https://app.c4bridge.io**.
2. Connect with the existing Director IP and API token.
3. Find that light in the **Lights** panel.
4. Compare the displayed state with the real light.
5. Press **Off** and confirm only that light turns off.
6. Press **On** and confirm it returns to its configured/default-on brightness.
7. If it is a dimmer, move the brightness slider and confirm the physical level and reported state.

Do not mass-test multiple lights until one known device has behaved correctly.
