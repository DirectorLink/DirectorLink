# C4Bridge v0.1.0-alpha.8

One-owner local pairing.

## Goal

Stop requiring homeowners to copy the long C4Bridge API token from Composer.

The new first-use flow is:

```text
C4Bridge installed
      ↓
Composer shows short Pairing Code
      ↓
app.c4bridge.io
      ↓
enter code once
      ↓
browser receives owner credential
      ↓
normal authenticated use
```

## Security model

### Owner credential

- random UUID credential generated by Director
- persisted encrypted using DriverWorks persistence
- existing alpha credentials are preserved on upgrade
- no longer displayed in Composer
- stored only in the paired browser

### Pairing code

- 8 numeric digits
- shown in Composer as **Pairing Code**
- valid for 15 minutes
- rotates after every successful pairing
- never stored by the web app
- five failed attempts in one minute trigger a 60-second lock

The pairing code is sent in the `X-C4Bridge-Pairing-Code` header, not in the URL.

## API

New unauthenticated route:

```text
POST /v1/pair
X-C4Bridge-Pairing-Code: 12345678
```

Success returns the long owner Bearer credential once to the browser.

Every other API route still requires:

```text
Authorization: Bearer <owner credential>
```

## Composer properties

New:

- Pairing Code
- Pairing Status

The old **API Token** property remains only for upgrade compatibility and now displays:

```text
Hidden - use Pairing Code
```

## PWA

The old API-token input is removed.

A browser with an existing valid alpha credential can continue connecting without pairing again. A new browser enters the short Pairing Code once.

## Known deferred issue

KNX percentage dimming remains deferred in issue #11. Light On/Off remains validated and is not blocked by this release.
