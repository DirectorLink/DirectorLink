# DirectorLink v0.8.0

**Direct to Director. End-to-end integration. Open source.**

C4Bridge is now **DirectorLink**, at **directorlink.io**, with a simpler way to connect.

## What changed

- The driver is `DirectorLink.c4z`: a single device in the project, with no button in the Control4 app.
- **Pairing, once:** the owner connects with a pairing code from Composer. A new DirectorLink shows a code right away; later, the Composer action **New Pairing Code** creates one. Codes are shown as `1234 5678`, are valid for 15 minutes, work once, and give admin access. Five wrong codes lock pairing for a minute.
- **No more approvals:** the DirectorLink Access button and access requests (`/v1/auth/requests`) are gone. Other devices get keys from an admin (API console → Keys), and with remote access (coming) family members will join by invitation.
- **Fewer Composer properties:** Status, Version, API Status, Pairing Code, Pairing Status, API Keys, Door Control, Log Level and Inventory. The controller details and load history are in the console's System tab.
- The app moved to **https://app.directorlink.io**.
- The API console has its own site, **https://console.directorlink.io**: the API explorer, the live log and its recording level, system and connection diagnostics, and key management (roles, rename, revoke, create).
- **https://directorlink.io** introduces the project.
- API: `DirectorLink API`, `x-directorlink-role` for each operation's role, `Bearer realm="DirectorLink"`; `POST /v1/auth/pair` accepts the code with or without the space and answers `PAIRING_NOT_ACTIVE` when no code is active.
- The driver answers browsers from app.directorlink.io and console.directorlink.io (and localhost for testing). The old app.c4bridge.io is retired.

## Moving from C4Bridge

Control4 treats DirectorLink as a new driver, so it is added rather than updated:

1. Write down any room names you set in other languages.
2. In Composer, remove **C4Bridge** (its **C4Bridge Access** button goes with it).
3. Add `DirectorLink.c4z` to the project; its properties show a pairing code.
4. Set **Door Control** to Enabled if you open doors from the app.
5. Open https://app.directorlink.io, enter the controller address and the pairing code. The app gets the owner's admin key.
6. For the console, run **New Pairing Code** and pair https://console.directorlink.io the same way.

API keys, room names and the Door Control setting belong to the driver instance, so they start fresh.
