# DirectorLink v0.8.0

**Direct to Director. End-to-end integration. Open source.**

C4Bridge is now **DirectorLink**, at **directorlink.io**.

## What changed

- The driver is `DirectorLink.c4z`; its button in the Control4 app is **DirectorLink Access**.
- The app moved to **https://app.directorlink.io**.
- The API console has its own site, **https://console.directorlink.io**: the API explorer, the live log with its recording level, system and connection diagnostics, and API key management (roles, rename, revoke, create).
- **https://directorlink.io** introduces the project.
- The API is unchanged apart from its name: `DirectorLink API` in the description, `x-directorlink-role` for each operation's role, and `Bearer realm="DirectorLink"`.
- The driver answers browsers from app.directorlink.io and console.directorlink.io (and localhost for testing). The old app.c4bridge.io is retired.

## Moving from C4Bridge

Control4 treats DirectorLink as a new driver, so it is added rather than updated:

1. Write down any room names you set in other languages (or keep C4Bridge until they are copied over).
2. In Composer, remove **C4Bridge** from the project; its **C4Bridge Access** button goes with it.
3. Add `DirectorLink.c4z` to the project. **DirectorLink** and its **DirectorLink Access** button appear, and the button shows in the Control4 app under Security in its room within a few seconds.
4. Set **Door Control** to Enabled if you open doors from the app.
5. Open https://app.directorlink.io, enter the controller address and press **Request access**; press **DirectorLink Access** in the Control4 app. The first key is the owner's (admin).
6. For the console, open https://console.directorlink.io and use **Request admin access** the same way (or the pairing code from Composer).

API keys, room names and the Door Control setting belong to the driver instance, so they start fresh.
