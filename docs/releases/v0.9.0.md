# DirectorLink v0.9.0

**Direct to Director. End-to-end integration. Open source.**

DoorBird doorbells, and the first test of remote access.

## DoorBird

- `GET /v1/doorbells` lists each DoorBird with its camera and what happened last: the last ring, motion, gate or door opening, and keypad access, plus the last 20 events since the driver started.
- `POST /v1/doorbells/{id}/open` opens the gate or door wired to the DoorBird by pressing its button, exactly as the Control4 app does (the button runs the installer's choice, by default *Trigger Relay 1*). It needs the `doors` role and **Door Control** = Enabled, and every request is logged with the key used.
- The app shows a banner with the camera and an **Open gate** button when someone rings, and a doorbell section in its room.
- DirectorLink listens to the DoorBird driver's own events (doorbell, motion, relay, keypad, communication), so it works with any DoorBird the Control4 driver supports.

## Remote access — test

- A new Composer property, **Remote Access** (Off by default), makes DirectorLink keep one outgoing, encrypted connection to `api.directorlink.io`. **Remote Status** shows whether it is connected. Nothing is opened on the home network.
- This version is a test of the connection itself: requests that arrive through it can only read (viewer), and only the DirectorLink team's test tool can send them. Accounts, invitations and the app's remote mode come next.
- While switched off, nothing connects.

## Installing

Update DirectorLink in Composer (it loads without a reboot; keys and settings stay).
