# DirectorLink v1.15.0

**Direct to Director. End-to-end integration. Open source.**

Arm and disarm the alarm from the app, with your code.

DirectorLink is an independent project, not affiliated with Control4 or Snap One.

## Arm and disarm the alarm

Until now the app showed the alarm's state only. From 1.15.0 admins, and the members an admin allows, can arm and disarm each part of the alarm (each partition) from the app, at home or away:

- **Arm:** choose how (Away, Home, Night: the modes your alarm's driver offers), then type your alarm code.
- **Disarm:** type your alarm code. Also during the exit or entry delay, and to stop an alarm.
- **Your code, each time.** It goes to the alarm, which checks it, as the wall keypad does. DirectorLink never keeps it, on the controller or in the app, and never writes it in a log; it crosses no network in the clear, and DirectorLink's servers never see it. *Corrected on 2026-11-13:* Control4's Director, which logs at its debug level, writes each command it passes between drivers into its own log on the controller, the code with it. That log is readable only by the controller's root user, kept in memory, and gone within about 2 to 3 hours and at a restart. DirectorLink 1.16.0 sends the code encrypted to the DirectorLink · PIMA FORCE driver, so that log only sees scrambled text.
- **Whether it worked** shows in the alarm's state a moment later. A wrong code changes nothing, and the app says so.
- **History** (Settings → Controller → History) lists each arm and disarm sent, by whom and when.

It is off until you switch it on:

1. In Composer, set DirectorLink's **Alarm Control** property to **On** (Alarm Status must be On too).
2. Admins can arm and disarm. For a member, turn on **Arms and disarms the alarm** in Settings → Users.

At most 6 commands a person in 5 minutes, and 20 in the home in an hour, so that nobody can guess a code. Scenes, schedules and links never arm or disarm.

Any Control4 alarm works. With **DirectorLink · PIMA FORCE**, our new driver for PIMA FORCE panels, the app also knows when the panel can't be armed from Control4 (a panel whose firmware only reports), and says so instead of offering buttons.

## Also in this release

- **Remote access:** the relay's log now counts a replaced connection once. The cause of the short disconnections is documented: Cloudflare moves the home's traffic between its data centers, and the connection comes back within seconds.

## Installing

- **DirectorLink in Composer:** update it to 1.15.0, then set **Alarm Control** if you want it. No D1 migration.
- **The app** updates by itself. With an older controller it shows the alarm as before, without buttons.
- **The relay (Worker)** is deployed separately, for the log's count.

## For developers

- `POST /v1/alarm/{partitionId}/arm` `{"mode", "code"}` and `/disarm` `{"code"}`: sealed only, with Alarm Status and Alarm Control On, by admins and members with `alarm_control`; `202` when sent. `GET /v1/alarm` gives each partition `modes` and `control` `{allowed, available}`; `GET /v1/system` `features.alarm_arming` and `features.alarm_control`; the people's permissions gain `alarm_control`; the history gains kind `alarm`, only in sealed reads (ADR-091).
- DirectorLink's alarm agreement, version 1, for alarm drivers: [docs/ALARM_DRIVERS.md](../ALARM_DRIVERS.md).
- The cloud's `driver_connected` counts in `replaced` only the open connection a new one takes over (ADR-072, corrected). CI uses `actions/setup-python` 7.1.0.
