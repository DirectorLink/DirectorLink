# C4Bridge v0.1.0-alpha.6

Real-system dimmer fix and driver-update diagnostics.

## Dimmer fix

A Director snapshot showed the working native Control4 path for the tested Light V2 proxy uses:

```text
SET_BRIGHTNESS_TARGET
PERCENT = 0..100
```

Previous C4Bridge alpha builds used other parameter shapes and the physical dimmer did not change.

Alpha.6 now matches the exact command captured from the working Director path:

- On → existing validated preset command
- Off → existing validated preset command
- Brightness → `SET_BRIGHTNESS_TARGET` with `PERCENT = 0..100`

## Update/reload diagnostics

The same snapshot showed both:

```text
C4Bridge.c4z
C4Bridge (1).c4z
```

installed on Director, and after reboot the live project instance loaded `C4Bridge (1).c4z`.

Alpha.6 adds Composer-visible lifecycle diagnostics:

- Reload Counter
- Last Init Type
- Last Init Time
- Last Destroy Type
- Last Destroy Time

It also exposes authenticated `GET /v1/diagnostics` for recent C4Bridge command/state/lifecycle traces.

## Important update rule

Before selecting the release file in Composer, make sure the local filename is exactly:

```text
C4Bridge.c4z
```

Do not use `C4Bridge (1).c4z`, `C4Bridge (2).c4z`, etc.

## Test

1. Download alpha.6.
2. Ensure the downloaded file is named exactly `C4Bridge.c4z`.
3. Right-click the existing C4Bridge instance → **Update Driver**.
4. Do **not** reboot immediately.
5. Check whether Bridge Version changes to `0.1.0-alpha.6`.
6. Check **Last Init Type**:
   - desired: `DIT_UPDATING`
   - reboot path: `DIT_STARTUP`
7. Test one dimmer at 30% and 70%.

If hot update still fails, reboot only after recording the lifecycle fields.
