# C4Bridge v0.6.0

Doors and gates on KNX relays, and room names in several languages.

## Relays (KNX Contact/Relay)

- `GET /v1/relays` / `GET /v1/relays/{relayId}` — each KNX Contact/Relay device with its room and relay state (`open`, `closed`, or `null` until the relay reports a change)
- `POST /v1/relays/{relayId}/pulse` — close the relay and open it again after 500 ms: opens a door or gate, the same way Control4's Relay Door, Gate and Garage Door Controllers trigger it
- `PATCH /v1/relays/{relayId}` with `{"state": "open" | "closed"}` — hold the relay in a state
- Every relay command is logged with the API key and client address that sent it.
- Devices of type `relay` link to `/v1/relays/{id}`; `/v1/system` counts `inventory.relays`.

C4Bridge sends the driver's own commands (Open Relay / Close Relay, relay 1) and listens to its Relay Opened / Relay Closed events for the state.

## Room names in several languages

- Rooms (and every `room` reference in lights, thermostats, blinds, cameras and relays) now carry `names`, e.g. `{"en": "Living room", "he": "סלון"}`.
- `PATCH /v1/rooms/{roomId}` with `{"names": {"en": "Living room"}}` sets them; an empty string removes a language. The Control4 name does not change. Names are stored on the controller and survive driver updates.

## Installing

Update the driver in Composer; it loads without a reboot. **Inventory** now also counts relays.

## Known issues

- Relay state from the Control4 app is validated on a real controller; sending pulse/open/close from the API is not yet (it would open a real door). Test it once from the API console before relying on it.
- Only relay 1 of each KNX Contact/Relay device is controlled (every relay device in the test project has one).
- KNX percentage dimming remains deferred (issue #11).
