# C4Bridge v0.1.0-alpha.2

First browser-to-Director integration test.

## Compatibility

- Minimum Director OS: **3.3.0**
- Web app: **https://app.c4bridge.io**
- Browser target for this alpha: current Chromium/Chrome
- LAN API port: **41999**

## Included

Everything from alpha.1, plus:

- authenticated read-only HTTP LAN API inside `C4Bridge.c4z`
- persistent per-install API token generated with `C4:UUID("RANDOM")`
- encrypted token persistence on Director
- CORS restricted to `https://app.c4bridge.io` and `https://c4bridge.io`
- read-only endpoints:
  - `GET /v1/system/info`
  - `GET /v1/rooms`
  - `GET /v1/devices`
- Chrome Local Network Access flow from the PWA
- live room/device rendering in the web app
- API status/port/token diagnostics in Composer

## Composer properties

After updating the driver, select C4Bridge in Composer and verify:

- **Bridge Version:** `0.1.0-alpha.2`
- **Status:** `Ready (discovery complete)`
- **API Status:** `Online - read-only alpha`
- **API Port:** `41999`
- **API Token:** a generated UUID

## Browser test

1. Open **https://app.c4bridge.io** in Chrome.
2. Enter the Director's LAN IPv4 address, for example `192.168.1.50`.
3. Paste the **API Token** from the C4Bridge Composer properties.
4. Click **Connect & test**.
5. Allow Local Network Access when Chrome prompts.
6. C4Bridge should show live Director version, room count, device count, room names, and normalized devices.

## Security

The API is read-only in this release. Every data request requires the per-install Bearer token. Browser CORS responses are restricted to the official C4Bridge origins.

The token flow is temporary alpha infrastructure. A proper first-use pairing flow will replace manual token copying before stable V1.
