# DirectorLink v1.16.0

**Direct to Director. End-to-end integration. Open source.**

Your alarm code out of Control4's logs, and arming without a code if you choose.

DirectorLink is an independent project, not affiliated with Control4 or Snap One.

## Your code, sealed to the alarm's driver

1.15.0 never logged your code, but Control4 itself did: its debug log on the controller records every command one driver sends another, for a few hours. With **DirectorLink · PIMA FORCE 1.2.0**, DirectorLink now seals each arm and disarm to the PIMA driver, which alone can open it. Control4's log sees only scrambled text. A sealed command that is replayed, more than a minute old, or meant for another action is refused.

## Arm, or arm and disarm, without a code

If you want it, an admin can let DirectorLink arm (or arm and disarm) without typing a code. The alarm's driver then uses its own code (DirectorLink keeps none). Two switches, both needed:

1. In Composer, the PIMA driver's **DirectorLink Without Code**: Arm only, or Arm and disarm.
2. In the app, **Settings → Alarm** (admins): the same choice.

The lower of the two applies. Arming then goes straight from the mode; disarming asks you to confirm. **Every disarm without a code is told to the admins** on their phones (Settings → Alerts: "The alarm is disarmed without a code", on by default). The history marks it too.

## Also in this release

- **Shabbat mode**, from DirectorLink · PIMA FORCE 1.1.0, is named in the app in all four languages.
- **Schedules:** the editor shows **On your holidays** only when your home has holidays (Schedules → Holidays), or the schedule already uses it.

## Installing

- **DirectorLink in Composer:** update it to 1.16.0. No Worker change and no D1 migration.
- **DirectorLink · PIMA FORCE:** update it to 1.2.0 for the sealed code and the without-code switch.
- **The app** updates by itself.
