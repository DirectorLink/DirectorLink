# C4Bridge v0.1.0-alpha.5

Fixes explicit dimmer level control after real-system alpha.4 testing.

## Real-system status

- Light On: validated
- Light Off: validated
- Brightness slider: failed in alpha.4 and is corrected in this release

## Root cause

The alpha.4 dimmer path used `LIGHT_BRIGHTNESS_TARGET_PERCENT`.

Control4's official sample Light V2 protocol driver handles `SET_BRIGHTNESS_TARGET` by reading:

```lua
tParams.LIGHT_BRIGHTNESS_TARGET
tParams.RATE
```

Alpha.5 now matches that contract for explicit dimmer targets.

## Mapping

- On → `LIGHT_BRIGHTNESS_TARGET_PRESET_ID = 1`
- Off → `LIGHT_BRIGHTNESS_TARGET_PRESET_ID = 2`
- Brightness → `LIGHT_BRIGHTNESS_TARGET = 0..100`, `RATE = 0`

The On/Off mapping is kept unchanged because it is already validated on the real Director.

## Test

Update the existing C4Bridge driver to alpha.5, connect the PWA, and test one dimmable light:

1. set 30%
2. confirm physical brightness changes
3. wait for Director confirmation in the PWA
4. set 70%
5. confirm again

Do not change the generic light adapter further unless the real proxy state provides evidence that another path is required.
