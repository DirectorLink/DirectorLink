# DirectorLink v1.3.0

**Direct to Director. End-to-end integration. Open source.**

DirectorLink 1.3: pairing never sends the code, the API console's key lasts a day, the app finds the controller by itself, Sign in with Apple, and Turn off all from Home.

## Pairing never sends the code

- The app and the API console now pair with CPace (ADR-039). They prove they know the pairing code without sending it, and the new key comes back sealed.
- Someone on the network can't read or take the code. Anyone in the middle gets one guess per attempt, and each guess counts as a wrong code.
- Nothing changes for you: type the code from Composer and tap Connect.
- **With a DirectorLink older than 1.3.0**, the app warns that the code would travel unprotected and asks you to update DirectorLink in Composer. Only **Pair anyway** pairs the old way.
  - The warning belongs to the controller it was about: typing another address, or finding another controller, clears it.
- **A controller whose DirectorLink failed its security self-test** now says so: nothing to update, ask the installer. **Pair anyway** is still offered there.
- Scripts still pair by sending the code.

## The API console's key lasts a day

- The console sends its key openly with every request, so the key it pairs for itself now expires after 24 hours (ADR-040).
- The Connection screen shows the time left. After that the console says *Your console key expired* and asks for a new pairing code from Composer.
- Console keys paired before 1.3.0 get one more day from the update. Keys made in the Keys tab are unchanged.
- Expired keys, and the invitations they made, are removed within a minute.
- People and devices shows when a key expires.

## Find my controller

- On a computer or an Android phone, the pairing screen can now look for the controller.
- Tap **Find my controller**. The app tries the addresses homes use most, starting with the one used before, for up to 30 seconds. It then fills in the address; you still enter the pairing code.
- It sends nothing but a health check, never a key or a code.
- It is not offered on iPhone or iPad, which pair through the account.

## Sign in with Apple

- **Sign in with Apple** is available next to Google. The app shows only the ways to sign in that work, and a device on which nobody signs in still contacts nobody.
- **An invitation opened with another email address** (for example Apple's Hide My Email) now asks the home's owner to approve it (ADR-041).
  - The owner sees who is asking and a 6-digit code to compare with the person they invited.
  - Once the owner approves, the invitation finishes by itself.
  - Only the owner approves.
- **When someone stops using Sign in with Apple** for DirectorLink, or deletes their Apple Account, that sign-in is removed and the account is signed out. Homes and family access stay.
  - An account left with no way to sign in, and owning no home, is deleted.
  - An owner's account stays for its home, without the person's name and email.
  - The privacy page says how long an unused account is kept.

## Turn off all from Home

- **Where:** tap a summary chip on Home ("7 lights on", "3 AC on", "4 blinds open"). Next to Show all there is now **Turn off all 7**, **Turn off all 3** or **Close all 4**, for members and admins. Viewers don't see it.
- **What it touches:** what the list shows at that moment. That is the lights that are on; the AC, floor heating and thermostats that are not Off; or the open blinds. Rooms you hide are left alone, and nothing that opens doors is touched.
- **Confirm:** the first tap asks **Tap again to turn off 7**, with Cancel, for 5 seconds. There is no undo.
- **One request:** it goes to the controller in one request, so it's as quick through the account as at home.
- **Results:** the app names any device that didn't turn off, with its room.

## For developers

- **Pairing:** `POST /v1/auth/pair` in two steps with `cpace` (the session, the nonces, the shares, the confirmations; CPACE-X25519-SHA512, draft-irtf-cfrg-cpace-21).
  - New problems `PAIRING_SESSION_EXPIRED` and, on a controller whose lock failed, `503 LOCK_UNAVAILABLE`. `PAIRING_CODE_EXPIRED` is now actually sent.
  - The vectors are in `tests/vectors/cpace.json`.
- **Keys:** `expires_in` on pairing (60 s to 30 days), `expires_at` on keys, and `401 KEY_EXPIRED`.
- **Health:** `GET /v1/health` includes `product: "directorlink"`.
- **Turn off all:** `POST /v1/off` with `type` (`lights`, `climate`, `blinds`) and `device_ids`, for members and above.
- **Cloud:**
  - `GET /auth/providers`.
  - Join requests: `/v1/join` with `ask_owner`; `GET` and `DELETE /v1/join/{home}/{invitation}`; `GET /v1/homes/{home}/join-requests`; `POST …/join-requests/{id}`.
  - `POST /auth/apple/notifications`.
  - D1 migration 0005.
  - The cloud tests now run in CI.
- Every change is additive; `api_version` stays `"1"`.

## Installing

- Update DirectorLink in Composer as usual (no reboot; keys, scenes and schedules stay). The app updates by itself; reload an app that was open during the update.
- Until the driver is updated, pairing a new device shows the "older DirectorLink" warning.
- **Rename a script key named exactly "DirectorLink Console" before updating.** Such a key is taken for the console's own key and expires a day after the update.
- **Going back to 1.2.x:**
  - Keys stay, but their expiry is dropped at the next save, so an old console key works until you revoke it by hand.
  - The 1.3.0 app then warns at every pairing, and Turn off all sends one request per device.

## Known issues

- Find my controller has only been tested against a fake Director. If it misses your controller, type the address; the installer can tell you, or find it in Composer.
- A key's expiry follows the controller's clock. A clock set far back makes a key last longer, but never more than 30 days.
- Pairing on the CORE-1 is estimated at under a second, not yet measured.
